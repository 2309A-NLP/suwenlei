# 日程提醒智能体 — 软件设计文档

> 工单编号：人工智能NLP-Agent数字人项目-日程提醒智能体任务
> 文档版本：V1.0

---

## 1. 需求概述

构建一个「日程提醒智能体」，通过自然语言对话实现日程的 **增 / 删 / 改 / 查**，
支持 **循环日程**，并在日程到点时主动进行 **温馨提醒**。所有日程信息（事项内容、
时间、循环规则）必须持久化保存到 **数据库**。

### 典型对话

| 用户 | 智能体 |
| --- | --- |
| 添加日程：下午 5 点开会 | 已记录：当天 17:00 开会，到点提醒 |
| 我今天的日程有哪些？ | 您今天的日程包括：1. 08:00 提醒您起床 …… |
| 删除日程 1 | （确认后）已经删除日程 1，删除的日程内容是：08:00 提醒您起床 |

## 2. 功能清单

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 添加日程 | 自然语言 / 标准格式添加 | 口语化时间（下午 5 点）→ 24 小时制（17:00） |
| 循环日程 | 每天 / 工作日 / 周末 / 指定星期 | 7 位循环规则 `YYYYYYY` |
| 查询日程 | 今天 / 明天 / 全部 | 带编号，便于删除 |
| 删除日程 | 按编号删除 | **二次确认** 后才删除 |
| 完整性引导 | 缺时间 / 缺内容时追问 | 不记录残缺数据 |
| 到点提醒 | 后台轮询，到点推送 | 4 种温馨话术，当天防重复 |
| 数据持久化 | SQLite | 任何操作都落库 |

## 3. 工具格式规范（set_schedule）

> 用于设置日程。接受 3 个参数，格式为 `HH:MM|YYYYYYY|事项内容`，所用标点必须为标准英文字符。

- `HH:MM`：时间（24 小时制）。
- `YYYYYYY`：循环规则，每位代表一天，**从星期一至星期日**，`1` 为循环、`0` 为不循环。
  例如 `1000100` 代表 **每周一和周五** 循环；`0000000` 表示不循环（一次性日程）。
- `事项内容`：提醒的具体内容。

**返回例子：** `15:15|0000000|提醒主人叫咖啡`

智能体把一切「添加日程」的请求都翻译成该格式，再交给唯一的写入入口 `set_schedule()` 落库，
从而保证「任何情况下都要调用数据库」。

## 4. 业务流程图

### 4.1 主对话流程

```
用户输入
   │
   ▼
意图识别 detect_intent ──► add / query / delete / confirm / cancel / unknown
   │
   ├─ add ─────► 解析时间/循环/内容 ──► 字段是否完整？
   │                                   │否 ──► 追问引导（结束本轮）
   │                                   │是 ──► set_schedule() 落库 ──► 读回标准格式确认
   │
   ├─ query ───► 查数据库 list_for_date ──► 编号展示，记录 序号→ID 映射
   │
   ├─ delete ──► 取编号 ──► 命中？ ──► 暂存 pending_delete ──► 请用户确认
   │
   ├─ confirm ─► 删除 pending_delete 对应日程 ──► 回执"已删除…"
   │
   └─ cancel ──► 清空 pending_delete
```

### 4.2 到点提醒流程（后台线程）

```
每 interval 秒：
   取当前 HH:MM 与日期
   ──► list_for_date(今天)  // 一次性当天 + 命中今天星期的循环日程
        └─ 对每条：time == 当前时间 且 last_reminded != 今天？
             └─ 是 ──► 生成温馨话术 ──► 更新 last_reminded=今天（防重复）──► 回调推送
```

## 5. 数据库设计

数据库：SQLite，文件 `schedules.db`；表：`schedules`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK AUTOINCREMENT | 主键 |
| time | TEXT NOT NULL | 提醒时间 `HH:MM`（24 小时制） |
| recurrence | TEXT NOT NULL DEFAULT '0000000' | 循环规则，7 位，周一~周日，1 循环 0 不循环 |
| content | TEXT NOT NULL | 事项内容 |
| schedule_date | TEXT | 一次性日程的具体日期 `YYYY-MM-DD`；循环日程为 NULL |
| enabled | INTEGER NOT NULL DEFAULT 1 | 是否启用 |
| last_reminded | TEXT | 最近一次提醒日期，用于当天防重复 |
| created_at | TEXT | 创建时间（本地时间） |

**设计要点**

- 一次性日程：`recurrence='0000000'` 且 `schedule_date=今天`，仅当天提醒一次。
- 循环日程：`recurrence` 含 `1`，`schedule_date=NULL`，按星期重复提醒。
- 「按日期取日程」由 `list_for_date()` 统一处理：合并「当天一次性」与「命中当天星期的循环」。

## 6. Prompt / 解析规则设计（NLP 要点）

为预判用户「生活化、口语化」的表达，提前在解析规则中覆盖以下表达方式（等价于在 prompt 中前置约束）：

- **时间段**：凌晨 / 早上·上午 / 中午 / 下午·午后·傍晚 / 晚上·今晚·夜里 → 自动换算 24 小时制。
- **时间点**：`下午5点`、`晚上八点半`、`9:30`、`X 点 Y 分`、中文数字（八点半、十二点）。
- **循环**：`每天`、`工作日`、`周末`、`每周一和周五`、`每周日`等 → 7 位规则。
- **直接格式**：用户也可直接输入 `15:15|0000001|提醒我买咖啡`。
- **完整性约束**：缺「时间」或「事项内容」时不落库，主动追问补全。
- **流程约束**：删除前必须二次确认，降低误删与模型不确定性。
