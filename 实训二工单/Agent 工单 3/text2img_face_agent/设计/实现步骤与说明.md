## 1. 任务目标

输入一张**面部图像**，由智能体自动产出：

1. **三张转头视图**：面部**左转**、**端正**、**右转**（左右偏转 ±30° 量级）；
2. 对每张视图进行**扩图（outpainting）**，向四周自然延展背景与肩部；
3. 输出一张复刻工单"最终效果图"版式的**对比拼图**。

要求：三视图与原图为同一人（五官/肤色/发型一致），角度自然、清晰、扩图无拼接痕迹。

---

## 2. 方案：通义图像后端 + LLM 工具编排 Agent

最终采用 **LLM tool-calling Agent** 架构：
**通义大模型（qwen-plus）作为"大脑"**，通过 function-calling 自主编排一组"图像工具"；
**图像生成由通义万相 `qwen-image-edit` 完成**（指令式图像编辑，擅长"保持同一个人、改变头部朝向"）。

```
                    ┌─────────────────────────────┐
   用户: 一张人脸 →  │  通义大模型 qwen-plus (Agent大脑) │
                    │  根据任务自主决定调用哪个工具      │
                    └──────────────┬──────────────┘
                                   │ function-calling
        ┌────────────┬─────────────┼─────────────┬──────────────┐
        ▼            ▼             ▼             ▼              ▼
   align_face   generate_view  generate_view  outpaint    make_contact_sheet
   (本地OpenCV)  (left/right/   (通义转头编辑)  (通义扩图)    (本地拼图)
                 front 通义编辑)
```

工具调用轨迹（实跑）：
`align_face → generate_view(left) → generate_view(front) → generate_view(right) → outpaint(×3) → make_contact_sheet`

### 2.1 为什么用通义 `qwen-image-edit` 而非本地 SD

| 验收要求 | 本地 SD1.5 (base) | 通义 qwen-image-edit |
|---|---|---|
| 面部特征保持（同一个人） | ✗ 纯提示词 img2img 易"换脸"；需额外 IP-Adapter | ✓ 指令式编辑，原生保持身份 |
| 明显且自然的转头 | ✗ 几何变形假、提示词转不动；需 ControlNet | ✓ 直接理解"向右转30°" |
| 部署成本 | 需下载 4~8GB 权重、占显存 | 云端 API，免本地大模型 |

实测对比后，本地 base 模型"转头必换人"，达不到验收；通义编辑一步到位，故定为最终方案。

### 2.2 各工具职责

| 工具 | 实现 | 对应验收点 |
|---|---|---|
| `align_face` | OpenCV Haar 检测+对齐裁剪为证件照构图 | 功能层面：确认输入为面部图像 |
| `generate_view` | 通义 `qwen-image-edit` + 朝向指令 + 身份约束 | 面部特征保持 / 角度准确性 |
| `outpaint` | **本地预扩灰画布 + 通义"只补四周"编辑 + 人脸校验重试** | 扩图：内容一致/连贯/无拼接 |
| `make_contact_sheet` | PIL 拼图（中文标注，微软雅黑） | 复刻工单"最终效果图"版式 |

### 2.3 扩图（outpaint）的关键设计

直接让 `qwen-image-edit` "扩图"不稳定（有时把主体擦成纯背景）。
最终做法（`tongyi_backend.expand_image`）：
1. **本地**先把视图居中贴到放大 1.35× 的灰色画布（边缘色取自原图四角）；
2. 让模型"**保持中心人物不变，只填满四周边框**" —— 主体像素被锁住，不会被擦除；
3. **生成后用人脸检测校验**，未检出则重试；最终仍失败则回退本地灰底画布，保证不空白。

## 3. 关键参数（`text2img_agent/config.py`）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `llm_model` | `qwen-plus` | Agent 大脑（function-calling） |
| `image_edit_model` | `qwen-image-edit` | 转头/扩图图像编辑后端 |
| `yaw_left/right` | -30° / +30° | 满足"±30° 以内"验收 |
| `outpaint_ratio` | 0.35 | 扩图四周扩展比例 |
| `max_retries` | 2 | API/扩图校验失败重试次数 |

## 4. 运行步骤

```bash
# 1) 激活环境（已含 opencv/pillow/numpy）
conda activate nlp_1

# 2) 安装依赖（核心是通义 SDK）
pip install -r requirements.txt        # dashscope / opencv-python / pillow / numpy

# 3) 配置通义 API Key
set DASHSCOPE_API_KEY=你的通义key       # Windows CMD
# 或 PowerShell:  $env:DASHSCOPE_API_KEY="你的key"

# 4) 运行
python run_demo.py            # LLM 自主编排（Agent 模式）
python run_demo.py pipeline   # 确定性流水线（稳定兜底，不经 LLM 决策）
python app.py --image inputs/original_face.png        # 同上，命令行
python app.py --ui            # Gradio Web UI（需 pip install gradio）

# 5) 验收评估
python evaluate.py            # 输出 docs/测试结果.json
```

产物在 `outputs/`：
- `00_aligned_face.png` 对齐后的输入脸
- `10_view_{left,front,right}.png` 三视图（转头）
- `20_outpaint_{left,front,right}.png` 三视图扩图
- `30_final_contact_sheet.png` 最终效果对比图

> 两种模式都会产出同样的文件；`run`（LLM）演示"智能体自主编排"，`run_pipeline`（确定性）用于稳定复现与回归。

## 5. 过程问题记录（踩坑与解决）

| # | 问题 | 原因 | 解决 |
|---|---|---|---|
| 1 | 本地 diffusers `from_pretrained` 报 `LocalEntryNotFoundError` | 本机无法访问 huggingface.co | 先改 ModelScope；后整体转为通义 API |
| 2 | 本地 SD1.5 转头"换人" | 纯 img2img 缺身份锁定（需 IP-Adapter/ControlNet） | 改用通义 `qwen-image-edit`，原生保身份 |
| 3 | 本地大模型下载 ~300KB/s，数小时 | 网络受限 | 通义云端方案，免本地权重 |
| 4 | `qwen-image-edit` 直接扩图把主体擦成空白 | 指令式编辑误判为"重绘背景" | 预扩灰画布+只补四周+人脸校验重试（见 2.3） |
| 5 | 专用 `image-out-painting` 模型报 url error | 该模型只收公网 URL，不收本地文件 | 用 `qwen-image-edit` 走预扩画布方案替代 |
| 6 | 拼图中文标签显示成方框 | PIL 默认字体无中文 | 加载微软雅黑/黑体（`_load_cjk_font`） |
| 7 | 旧评估脚本把侧脸判为"无人脸" | 仅用正脸 Haar 级联 | 评估器加 `profileface` 侧脸级联 + 翻转检测 |
| 8 | 生成图被美颜/化妆，与本人不像（磨皮、美白、瘦脸、像化了妆） | `qwen-image-edit` 对"证件照"默认理想化；旧提示词含"证件照风格/均匀柔和影室光"等会助推美化，且未禁止化妆 | 改写 `NO_BEAUTY_RULE`：显式禁止美颜+化妆（口红/粉底/眼影等）、要求保留素颜瑕疵；`IDENTITY_RULE` 去掉"均匀柔和影室光"、加"不要把人物变好看"，"证件照风格"改为"证件照构图"。改后需重跑覆盖 `outputs_photo2` |
