## 一、性能优化

### 1.1 响应速度优化

**现状**：端到端耗时约 176 秒，主要瓶颈在通义 API 调用（8 次工具调用）

| 优化项 | 方案 | 预期收益 |
|---|---|---|
| **并行化转头生成** | `generate_view(left/front/right)` 三次调用改为并发请求 | 减少 60~90 秒（串行→并行） |
| **并行化扩图** | `outpaint(×3)` 改为并发调用 | 减少 40~60 秒 |
| **结果缓存** | 对相同输入图像缓存中间产物（aligned_face、views） | 重复测试提速 90%+ |
| **API 请求池化** | 复用 HTTP 连接，减少握手开销 | 减少 5~10 秒 |

**实现优先级**：高（并行化）> 中（缓存）> 低（连接池）

```python
# 示例：并发生成三视图
from concurrent.futures import ThreadPoolExecutor

def generate_all_views_parallel(aligned_face):
    with ThreadPoolExecutor(max_workers=3) as executor:
        futures = {
            'left': executor.submit(generate_view, aligned_face, 'left'),
            'front': executor.submit(generate_view, aligned_face, 'front'),
            'right': executor.submit(generate_view, aligned_face, 'right')
        }
        return {k: f.result() for k, f in futures.items()}
```

### 1.2 成本优化

| 优化项 | 方案 | 预期收益 |
|---|---|---|
| **降低重试次数** | 当前 `max_retries=2`，根据实际成功率调整为 1 或增加预检 | 减少 20~40% API 调用 |
| **扩图校验优化** | 人脸检测改为轻量级模型（如 MediaPipe），避免重复调用 Haar 级联 | 减少本地计算耗时 |
| **按需生成** | 提供"仅生成三视图"或"跳过扩图"选项 | 按需降低 API 调用 50% |

## 二、质量优化

### 2.1 背景一致性增强

**现状问题**：测试报告指出"三视图背景灰度未完全统一"（端正偏亮、左右偏冷）

**解决方案**：

1. **后处理颜色归一化**（推荐）
   - 提取三张图的背景主色（通过边缘采样）
   - 计算目标灰度（三者均值或用户指定）
   - 用色彩映射（LUT）统一背景到目标灰度

2. **提示词强化**
   - 在 `generate_view` 和 `outpaint` 的提示词中显式指定"背景为中性灰 RGB(180,180,180)"
   - 适用场景：背景要求严格统一的证件照场景

```python
def normalize_backgrounds(images):
    """统一多张图的背景灰度"""
    bg_colors = [extract_bg_color(img) for img in images]
    target_gray = np.mean(bg_colors, axis=0)
    return [apply_color_mapping(img, src_bg, target_gray)
            for img, src_bg in zip(images, bg_colors)]
```

### 2.2 角度精确度提升

**现状**：仅通过人脸框中心跨度粗判角度差异，未精确测量 yaw 角

**解决方案**：

1. **集成 MediaPipe Face Mesh**
   - 提取 468 个面部关键点
   - 通过鼻尖、左右眼角等关键点计算精确 yaw/pitch/roll 角
   - 验收时可量化"左转 -28°、端正 2°、右转 31°"

2. **角度反馈闭环**
   - 生成后检测实际角度，若偏差 >5° 则调整提示词重新生成
   - 适用场景：对角度精度要求严格的场景

### 2.3 防过度美颜强化

**现状**：已通过 `NO_BEAUTY_RULE` 禁止美颜化妆，但仍可能出现磨皮现象

**增强方案**：
- 提示词追加："保留皮肤纹理、毛孔、痣、斑点等真实细节"
- 生成后检测对比：计算原图与生成图的纹理复杂度（高频分量），若下降 >20% 则标记"可能过度平滑"
- 如通义 API 支持"真实度/风格化"参数，调至最真实档

## 三、稳定性优化

### 3.1 失败恢复机制

| 场景 | 当前处理 | 优化方案 |
|---|---|---|
| API 调用失败 | 重试 2 次后抛异常 | 增加指数退避（0.5s → 2s → 5s），避免瞬时限流导致全失败 |
| 扩图人脸校验失败 | 回退灰底画布 | 记录失败原因并尝试降低扩图比例重试 |
| 网络超时 | 默认超时（可能很长） | 设置明确的 `timeout=60s`，超时快速失败 |

### 3.2 异常输入处理

| 输入异常 | 当前处理 | 优化方案 |
|---|---|---|
| 无人脸图像 | `align_face` 失败报错 | 返回友好提示："未检测到人脸，请上传清晰正面照" |
| 多人脸图像 | 选择最大人脸 | 增加用户确认："检测到 N 张人脸，将使用最大的一张" |
| 侧脸/遮挡 | 可能对齐失败 | 增加人脸质量评分（正面度/清晰度/遮挡检测），低于阈值时预警 |
| 过小图像（<256px） | 可能生成模糊 | 预先上采样到 768px，或提示"建议上传 512px 以上图像" |

## 四、功能扩展

### 4.1 多场景支持

**当前限制**：仅支持灰背景证件照风格

**扩展方案**：
1. **场景模板**：提供"室内/户外/白底/蓝底"等背景模板
2. **风格迁移**：扩图时保持原图背景风格（如"保持原图的办公室背景"）
3. **服装/配饰保持**：提示词增强"保持原图的黑色西装/白色衬衫/眼镜"

### 4.2 批量处理

**场景**：企业/学校需批量处理数百张照片

```python
def batch_process(input_dir, output_dir, max_workers=5):
    """批量处理文件夹内所有人脸图像"""
    images = glob(f"{input_dir}/*.png")
    with ThreadPoolExecutor(max_workers=max_workers) as executor:
        futures = [executor.submit(agent.run_pipeline, img) for img in images]
        results = [f.result() for f in futures]
    return results
```
