# RAG工单11 - 优化内容总结

> **项目**: 人工智能NLP-RAG项目-11-Embeddings模型微调  
> **优化时间**: 2026年6月  
> **优化目标**: 通过微调Embedding模型提升RAG检索准确性

---

## 一、优化背景

通用Embedding模型（如bge-base-zh-v1.5）在大规模网络语料库上预训练，但在专业领域（如招股说明书）存在"语义鸿沟"：
- 专业术语理解不准确
- 特定实体关系识别困难
- 检索结果不理想

---

## 二、优化方案

### 2.1 核心优化：Embedding模型微调

| 优化项 | 内容 |
|--------|------|
| **基础模型** | BAAI/bge-base-zh-v1.5 (768维) |
| **微调方法** | TripletLoss (三元组损失) |
| **训练数据** | 200条三元组 (query, positive, hard_negative) |
| **评估数据** | 30条随机抽取 |
| **训练轮数** | 2 Epochs |
| **学习率** | 2e-5 |
| **批大小** | 1 |

### 2.2 数据准备优化

| 优化项 | 内容 |
|--------|------|
| **PDF解析** | 548页招股说明书 → 1144个文本分块 |
| **三元组生成** | 使用DeepSeek API生成高质量训练数据 |
| **负例策略** | hard_negative：从邻近chunk中挑选语义相近但信息不同的文本 |
| **质量控制** | 过滤无效query，随机种子固定确保可复现 |

### 2.3 评估体系优化

| 优化项 | 内容 |
|--------|------|
| **评估指标** | 22项完整指标（原5项） |
| **指标分类** | 召回类、精确率类、命中率、排序质量 |
| **评估方式** | 每次随机抽取30条query，避免数据偏差 |

---

## 三、优化效果

### 3.1 微调前后对比（随机抽取30条）

| 指标 | 微调前 | 微调后 | 提升 |
|------|--------|--------|------|
| **Recall@1** | 46.67% | **60.00%** | **+13.33%** |
| **MRR** | 0.6361 | **0.7168** | **+8.08%** |
| **NDCG@3** | 0.6516 | **0.7385** | **+8.69%** |
| Recall@3 | 76.67% | 83.33% | +6.67% |
| Recall@5 | 80.00% | 83.33% | +3.33% |
| MAP | 0.6361 | 0.7168 | +8.08% |

### 3.2 核心提升

- **首条命中率(Recall@1)**: 提升13.33%，用户提问时首条就找到正确答案的概率大幅提升
- **排序质量(MRR)**: 提升8.08%，正确答案在搜索结果中的平均排名更靠前
- **综合指标(MAP)**: 提升8.08%，整体检索质量改善

## 五、问题与解决方案

| 问题 | 解决方案 |
|------|---------|
| 评估数据非随机，结果偏高 | 改用random.sample()随机抽取 |
| Epoch=5过拟合 | 改用Epoch=2，提前停止 |
| Batch Size=8不稳定 | 改用Batch Size=1，逐样本更新 |
| Milvus维度不匹配 | 重建768维向量库 |
