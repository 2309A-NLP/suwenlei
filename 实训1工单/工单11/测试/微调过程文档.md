## 一、微调目标

在专业数据（招股说明书）上微调Embedding模型，弥补通用模型在专业领域的"语义鸿沟"，提升RAG系统检索准确性。

**验收标准**: 微调后的Embedding模型的检索效果比微调前要好，要有数据指标支撑。

## 三、数据准备过程

### 3.1 PDF解析

从招股说明书PDF提取文本分块：

```
输入: 招股说明书1.pdf (548页)
输出: 招股说明书1_chunks.csv (1144个chunk)
处理时间: ~10秒
分块策略: 按段落分割，最大800字符
```

### 3.2 三元组数据生成

使用DeepSeek API生成训练三元组 (query, positive, hard_negative)：

```
训练数据: 200条三元组
评估数据: 30条 (随机抽取)
数据来源: 从1139个chunk中随机选取200个
生成方式: 
  - query: LLM根据chunk生成自然语言问题
  - positive: chunk原文
  - hard_negative: LLM从邻近chunk中挑选语义相近但信息不同的文本
```

### 3.3 数据质量控制

- 过滤长度<5的无效query
- 选择长度相近的chunk作为hard_negative
- 随机种子固定(seed=42)确保可复现

## 五、评估过程

### 5.1 评估方法

- **评估数据**: 30条随机抽取的query
- **语料库**: 1139个chunk
- **评估方式**: 计算每个query与所有chunk的余弦相似度，排序后计算指标
- **评估工具**: evaluate.py (自定义脚本)

### 5.2 评估指标

共22项指标，覆盖4大类：
- **召回类**: Recall@K (K=1,3,5,10)
- **精确率类**: Precision@K, F1@K
- **命中率**: Hit Rate@K
- **排序质量**: NDCG@K, MRR, MAP, Average Rank

### 5.3 评估结果

| 指标 | 微调前 | 微调后 | 提升 |
|------|--------|--------|------|
| **Recall@1** | 63.33% | **70.00%** | **+6.67%** |
| **MRR** | 0.7637 | **0.8306** | **+6.69%** |
| **NDCG@3** | 0.7718 | **0.8472** | **+7.54%** |
| Recall@3 | 86.67% | 93.33% | +6.67% |
| Recall@5 | 96.67% | 96.67% | - |
| Recall@10 | 100% | 100% | - |
| MAP | 0.7637 | 0.8306 | +6.69% |

**结论**: 微调后模型在首条命中率(Recall@1)提升6.67%，排序质量(MRR)提升6.69%，验证微调有效。

## 六、问题记录

### 6.1 问题一：评估数据非随机抽取

**问题**: 初始版本按顺序取前30条作为评估数据，结果偏高(Recall@1提升40%)。

**解决**: 改用`random.sample()`随机抽取30条，提升幅度回归真实值(6.67%)。

**教训**: 评估数据必须随机抽取，否则结果不具代表性。

### 6.2 问题二：Epoch数选择

**问题**: 初始尝试Epoch=5，但第3个epoch后评估指标开始下降(过拟合)。

**解决**: 改用Epoch=2，在过拟合前停止训练。

**教训**: 小数据集(200条)容易过拟合，建议从2个epoch开始。

### 6.3 问题三：Batch Size选择

**问题**: 初始尝试Batch Size=8，但TripletLoss在小数据集上不稳定。

**解决**: 改用Batch Size=1，逐样本更新，梯度更精确。

**教训**: 小数据集时小Batch Size效果更好。

### 6.4 问题四：Milvus维度不匹配

**问题**: 微调后模型输出768维，但Milvus中存储的是128维旧向量，导致检索全部失败。

**解决**: 重建Milvus集合，使用768维向量。

**教训**: 模型更换后必须同步更新向量库。
