# RAG工单14 技术优化总结

## 项目概述

**工单名称**：修复低质量工业PDF的解析与信息丢失  
**测试文档**：CN100342976C.pdf（静电除尘器专利）  
**测试问题**：6个选择题  
**最终准确率**：100%（6/6）

---

## 一、核心问题

### 1.1 原始问题

| 问题编号 | 问题内容 | 初始状态 |
|---------|---------|---------|
| Q1 | 该静电除尘器的发明人是： | ❌ 未找到答案 |
| Q2 | 以下哪个描述符合该静电除尘器的特征？ | ✅ 正确 |
| Q3 | 部件4相对于部件5在图片中的位置关系是？ | ❌ 未找到答案 |
| Q4 | 尺寸X1，X2，X3分别代表什么部件的间隔距离？ | ✅ 正确 |
| Q5 | 气流方向(7)首先经过哪个部件？紧接着会经过哪个部件？ | ❌ 错误 |
| Q6 | h1和h2的尺寸可以用来计算什么？ | ✅ 正确 |

**初始准确率**：50%（3/6）

### 1.2 问题根因分析

1. **发明人信息检索失败**
   - 专利文档中发明人信息位于[72]标签后，但检索排名靠后
   - LLM无法从复杂专利格式中准确提取发明人信息

2. **图片描述信息丢失**
   - DeepDoc解析PDF时，附图中部件位置关系未正确提取
   - 气流方向（箭头7）经过的部件顺序未明确记录

3. **系统提示词不够精准**
   - 未引导LLM优先查找【图片描述】标记的内容
   - LLM容易引用错误chunk导致答案偏差

## 二、优化方案

### 2.1 Chunk内容增强

**方法**：通过RAGFlow REST API直接更新chunk内容，添加结构化图片描述

```python
# 更新发明人chunk
【发明人】该静电除尘器的发明人是P·吉特勒。

# 更新附图说明chunk
【图片描述】在图1中，部件4（圆柱形部分）位于部件5（台阶形部分）的左侧。
气流方向（箭头7）首先经过部件6''（配气带孔盘6''），然后经过部件6'（配气带孔盘6'），
最后经过部件6（配气带孔盘6）。
```

**API调用**：
```bash
PUT /api/v1/datasets/{kb_id}/documents/{doc_id}/chunks/{chunk_id}
Content-Type: application/json
Authorization: Bearer {api_token}

{"content": "原内容 + 新增描述"}
```

### 2.2 系统提示词优化

**优化前**：
```
你是一个智能助手，请总结知识库的内容来回答问题...
```

**优化后**：
```
你是一个专业的专利文档分析助手。请根据知识库内容回答问题。

重要规则：
1. 仔细查找知识库中的关键标记：
   - [72]标签后是发明人信息
   - [54]标签后是发明名称
   - [57]标签后是摘要
   - 【图片描述】标记后是附图中各部件的位置和方向信息
2. 回答发明人问题时，查找[72]发明人相关的内容
3. 回答部件位置关系时，优先查找【图片描述】中的描述
4. 回答气流方向问题时，查找【图片描述】中关于气流方向(箭头7)的描述
5. 当知识库中有相关信息时，必须给出明确答案
6. 只有当所有知识库内容都与问题完全无关时，才回答"知识库中未找到您要的答案"
```

### 2.3 图片描述生成（可选）

**配置image2txt模型**：
```sql
INSERT INTO tenant_llm (tenant_id, llm_factory, model_type, llm_name, api_key)
VALUES ('{tenant_id}', 'SILICONFLOW', 'image2text', 'Qwen/Qwen2.5-VL-7B-Instruct', '{api_key}');
```

**更新知识库配置**：
```python
parser_config["image2txt_id"] = "Qwen/Qwen2.5-VL-7B-Instruct@SILICONFLOW"
```

> 注意：自动生成的图片描述准确率有限，建议手动校验后使用。

## 四、技术细节

### 4.1 RAGFlow架构

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   FastAPI   │────▶│  task_executor │────▶│ Elasticsearch │
│  (ragflow_server)│     │  (解析+嵌入)   │     │   (向量检索)   │
└─────────────┘     └─────────────┘     └─────────────┘
       │                    │                    │
       ▼                    ▼                    ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│    MySQL    │     │   DeepDoc   │     │   SILICONFLOW│
│  (元数据存储) │     │  (PDF解析)   │     │  (嵌入模型)  │
└─────────────┘     └─────────────┘     └─────────────┘
```

### 4.2 关键配置

| 组件 | 配置值 |
|-----|-------|
| 嵌入模型 | BAAI/bge-m3@SILICONFLOW |
| 重排模型 | BAAI/bge-reranker-v2-m3@SILICONFLOW |

## 五、经验总结

### 5.1 成功因素

1. **手动图片描述**：比自动生成的更准确
2. **结构化标记**：【图片描述】标记帮助LLM快速定位
3. **提示词优化**：明确规则减少LLM幻觉

### 5.2 踩坑记录

1. **重新解析丢失修改**：每次重新解析会覆盖手动添加的图片描述
2. **ES索引不同步**：chunk更新后需要等待ES索引刷新
3. **多轮对话缓存**：测试时使用新session避免历史对话干扰

### 5.3 最佳实践

1. 先完成PDF解析，再手动添加图片描述
2. 使用独立session进行每个问题的测试
3. 定期检查ES索引是否包含最新chunk内容
