# RAG工单12 部署文档

## 一、项目概述

本项目为 **LightRAG与传统RAG对比评估系统**，基于两份招股说明书（武汉兴图新科 + 武汉力源信息）构建知识图谱，并通过RAGAS指标对比两种检索架构的性能差异。

### 核心组件

| 组件 | 说明 |
|------|------|
| RAG系统 | Milvus向量检索 + BM25 + RRF混合检索 + bge-reranker重排 |
| LightRAG系统 | 知识图谱检索（hybrid模式）+ bge-m3嵌入 |
| LLM | DeepSeek-chat（API调用） |
| 嵌入模型 | bge-m3（本地，1024维） |
| 重排模型 | bge-reranker-v2-m3（本地） |

### 3.3 安装并启动Milvus

```bash

python -c "from pymilvus import connections; connections.connect('default', host='localhost', port='19530'); print('Milvus连接成功')"
```

### 3.4 下载模型

模型文件需要预先下载到 `model/` 目录：


> **国内加速：** 使用HF镜像 `HF_ENDPOINT=https://hf-mirror.com git clone ...`

将以下文件放入 `uploads/` 目录：

```

├── 招股说明书1.pdf              # 武汉兴图新科电子股份有限公司
```

## 六、运行测试

### 6.1 运行16题对比测试

```bash
python full_test.py
```

测试流程：
1. LightRAG查询（16题）
2. 读取RAG结果
3. RAGAS评分
4. 对0分题自动重新检索
5. 生成评估报告

**输出：**
- 控制台：指标对比表 + 逐题对比
- 文件：`results/rag_vs_lightrag_report_final.json`

### 6.2 测试结果解读

| 指标 | 含义 | 值域 |
|------|------|------|
| answer_relevancy | 答案与问题的相关性 | 0-1，越高越好 |
| context_precision | 检索上下文的精确度 | 0-1，越高越好 |
| context_recall | 检索上下文的召回率 | 0-1，越高越好 |
| faithfulness | 答案对上下文的忠实度 | 0-1，越高越好 |

## 九、常见问题

### Q1：LightRAG报错 `This event loop is already running`
**原因：** lightrag-hku在async上下文中调用`run_until_complete`
**解决：** 确保 `full_test.py` 顶部有 `import nest_asyncio; nest_asyncio.apply()`

### Q2：reranker报错 `TypeError: list indices must be integers or slices`
**原因：** ragas_py310环境的transformers版本与bge-reranker不兼容
**解决：** 测试时使用 `skip_reranker=True` 跳过重排

### Q3：Milvus连接失败
**解决：**
```bash
# 检查Milvus是否运行
docker ps | grep milvus
# 重启
docker restart milvus-standalone
```

### Q4：模型加载慢
**说明：** bge-m3（4.4GB）首次加载需要时间，后续会缓存在内存中。建议使用GPU加速。

### Q5：DeepSeek API Key被掩码
**原因：** 工具安全机制自动掩码sk-开头的字符串
**解决：** 手动用记事本编辑 `llm.py` 第16行
