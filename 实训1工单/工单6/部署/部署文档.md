# RAG工单6 部署文档

## 1. 项目概述

### 1.1 项目简介
RAG工单6是一个基于PDF文档的智能问答系统，采用混合检索架构（向量检索+BM25全文检索+RRF融合+Reranker重排）。系统通过解析PDF文档（招股说明书）构建向量数据库，实现对文档内容的语义检索和问答。

### 1.2 核心功能
- **混合检索**：向量检索 + BM25全文检索 + RRF融合
- **重排序**：bge-reranker-v2-m3交叉编码器 + 可选LLM重排
- **多文档路由**：根据问题内容自动判断搜索哪个文档
- **多轮对话记忆**：支持上下文理解，支持指代消解
- **中英文支持**：支持中文和英文问答

### 1.3 技术架构
```
用户请求 → FastAPI后端 → 查询理解 → 文档路由 → 向量检索+BM25 → RRF融合 → Reranker重排 → LLM生成 → 返回答案
                                    ↓
                              Redis对话记忆
```

## 2. 环境要求

### 2.1 操作系统
- Windows 10/11
- WSL (Windows Subsystem for Linux)

### 2.2 Python环境
- Python 3.11+（推荐使用项目自带的.venv虚拟环境）
- 虚拟环境路径：`E:\桌面\工单\RAG工单6\.venv`

### 2.3 依赖服务
- **Milvus**：向量数据库（运行在Windows上，端口19530）
- **Redis**：对话记忆存储（端口6379）
- **DeepSeek API**：大语言模型API

### 2.4 模型文件
- **bge-m3**：嵌入模型（1024维向量）
- **bge-reranker-v2-m3**：重排序模型（交叉编码器）

## 5. API接口说明

### 5.1 健康检查
```
GET /api/health
```
返回服务状态、引擎状态、后端类型、Redis可用性、检索模式等信息。

### 5.2 文件上传
```
POST /api/upload
Content-Type: multipart/form-data
```
上传PDF文件，自动完成解析+分块+向量+Milvus入库。

### 5.3 文件列表
```
GET /api/files
```
获取已上传的文件列表。

### 5.4 删除文件
```
DELETE /api/files/{filename}
```
删除指定的上传文件及对应的CSV分块文件。

### 5.5 知识库重载
```
POST /api/reload
```
重新加载知识库（从CSV重新加载，不重新解析PDF）。

### 5.6 问答接口
```
POST /api/ask
Content-Type: application/json

{
  "question": "问题内容",
  "top_k": 5,
  "conversation_id": "可选的会话ID",
  "search_mode": "hybrid",
  "lang": "zh"
}
```
核心问答接口，支持中英文和多轮对话。

### 5.7 对比接口
```
POST /api/compare
Content-Type: application/json

{
  "question": "问题内容",
  "top_k": 5,
  "conversation_id": "可选的会话ID",
  "lang": "zh"
}
```
同时返回RAG（基于PDF检索）和纯LLM（无上下文）的回答，用于对比分析。

### 5.8 检索配置接口
```
GET /api/search/config
```
获取当前检索配置（模式、权重等）。

```
POST /api/search/config
Content-Type: application/json

{
  "search_mode": "hybrid",
  "vector_weight": 0.6,
  "bm25_weight": 0.4,
  "use_reranker": true,
  "use_llm_rerank": false
}
```
设置检索模式和权重。

### 5.9 LLM重排接口
```
POST /api/rerank
Content-Type: application/json

{
  "question": "问题内容",
  "top_k": 5
}
```
用DeepSeek API对候选文档重新评分。

### 5.10 对话历史查询
```
GET /api/conversations/{conversation_id}
```
获取指定会话的对话历史。

### 5.11 删除对话
```
DELETE /api/conversations/{conversation_id}
```
删除指定会话的对话历史。

### 5.12 清空所有对话
```
DELETE /api/conversations
```
清空所有会话的对话历史。

### 5.13 查询理解调试
```
GET /api/understand?q=问题内容
```
返回查询理解结果（意图识别、扩展查询等）。

### 5.14 路由调试
```
GET /api/debug_route?q=问题内容
```
返回路由结果和检索来源。

## 7. 使用说明

### 7.1 上传文档
1. 访问前端页面 `http://localhost:8888`
2. 点击"上传文件"按钮
3. 选择PDF文件上传
4. 系统自动完成解析、分块、向量化、入库

### 7.2 提问问答
1. 在输入框输入问题
2. 选择语言（中文/英文）
3. 选择检索模式（混合/向量/BM25）
4. 点击"提问"或"对比分析"
5. 查看回答结果和引用来源

### 7.3 多轮对话
1. 首次提问后，系统会生成一个`conversation_id`
2. 后续提问时传入`conversation_id`，系统会自动关联对话历史
3. 支持指代消解（如"这个公司"、"那XX呢"）

### 7.4 对比分析
使用`/api/compare`接口可以同时查看：
- **RAG回答**：基于PDF检索的回答
- **纯LLM回答**：不使用文档上下文的回答
- **对比分析**：两种回答的一致性、详细程度等

### 7.5 检索模式切换
- **hybrid**：混合检索（向量+BM25+RRF融合）
- **vector**：仅向量检索
- **bm25**：仅BM25全文检索

## 8. 常见问题

### 8.1 服务启动失败
- 检查端口是否被占用
- 检查Python依赖是否完整安装
- 检查Milvus服务是否正常运行
- 检查Redis服务是否正常运行
- 检查模型文件是否存在

### 8.2 上传文件失败
- 确认文件格式为PDF
- 检查uploads目录权限
- 查看控制台错误日志

### 8.3 检索结果不准确
- 检查Milvus向量数据库是否正常
- 尝试调整检索模式和权重
- 使用`/api/debug_route`调试路由结果

### 8.4 LLM回答不准确
- 检查DeepSeek API密钥是否有效
- 查看API调用日志
- 尝试使用对比接口分析差异

### 8.5 对话记忆不工作
- 检查Redis服务是否正常运行
- 查看`/api/health`中的`redis_available`字段
- Redis不可用时会自动降级为内存存储（进程重启丢失）

### 8.6 Reranker加载失败
- 检查模型文件是否存在：`model/bge-reranker-v2-m3/`
- 检查torch是否正确安装
- 查看控制台错误日志

## 11. 与前序工单的对比

| 特性 | RAG工单5 | RAG工单6 |
|------|----------|----------|
| 检索方式 | Milvus向量检索 | 混合检索（向量+BM25+RRF） |
| 重排序 | 无 | bge-reranker-v2-m3 + 可选LLM重排 |
| BM25 | 无 | 完整BM25实现（jieba分词+倒排索引） |
| RRF融合 | 无 | Reciprocal Rank Fusion |
| 检索模式 | 固定 | 可切换（vector/bm25/hybrid） |
| 权重配置 | 无 | 可配置向量/BM25权重 |
| 文件结构 | 分离 | 合并（llm.py、models.py、search.py） |
| 模型数量 | 1个（bge-m3） | 2个（bge-m3 + bge-reranker-v2-m3） |
