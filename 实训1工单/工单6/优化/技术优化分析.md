# RAG工单6 技术优化分析

## 一、项目定位与核心架构

RAG工单6是混合检索增强生成系统的最终形态，在前序工单（向量检索 + TF-IDF）基础上，引入了**完整的混合检索架构**：

```
用户查询
  ↓
查询理解（意图识别 → 实体消歧 → 问题分解 → 查询扩展）
  ↓
文档路由（强匹配 → 弱匹配 → 全文档）
  ↓
┌─────────────────────────────────────────┐
│  向量检索（bge-m3 + Milvus）            │  ← 语义相似度召回
│  BM25全文检索（jieba分词 + 倒排索引）     │  ← 关键词精确匹配
│  RRF融合（Reciprocal Rank Fusion）       │  ← 多路结果归一化合并
└─────────────────────────────────────────┘
  ↓
Reranker重排序（bge-reranker-v2-m3）     ← 交叉编码器精细打分
  ↓
关键词补全检索（兜底召回）                ← 保证召回率
  ↓
LLM生成（三级降级：标准答案 → API → 本地提取）
  ↓
答案返回（含来源、分数、对话历史）
```

**与前序工单的架构对比：**

| 维度 | 工单2 | 工单5 | 工单6 |
|------|-------|-------|-------|
| 嵌入模型 | TF-IDF+SVD | bge-m3 | bge-m3 |
| 向量维度 | 128维 | 1024维 | 1024维 |
| 检索方式 | 仅向量 | 仅向量 | **混合（向量+BM25+RRF）** |
| 重排序 | 无 | 无 | **bge-reranker + 可选LLM重排** |
| 全文检索 | 无 | 无 | **BM25（jieba分词+倒排索引）** |
| 对话记忆 | 无 | Redis | Redis |
| 文件结构 | 分散 | 分散 | **合并（llm.py/models.py/search.py）** |

## 二、混合检索引擎

### 2.1 向量检索分支

**嵌入模型：** bge-m3（BAAI/bge-m3），1024维稠密向量

```python
# models.py — EmbeddingClient（单例+懒加载）
class EmbeddingClient:
    MODEL_DIR = 'model/bge-m3'
    EMBEDDING_DIM = 1024

    def encode(self, texts, batch_size=32):
        embeddings = self._model.encode(
            texts,
            batch_size=batch_size,
            normalize_embeddings=True  # L2归一化，配合Milvus内积(IP)度量
        )
        return np.array(embeddings, dtype=np.float32)
```

**向量存储：** Milvus（IVF_FLAT索引，内积度量，nlist=128）

```python
# search.py — MilvusStore
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=1024),

index_params = {"metric_type": "IP", "index_type": "IVF_FLAT", "params": {"nlist": 128}}
```

**优化点：**
- L2归一化 + 内积度量 = 等价于余弦相似度，但计算更快
- 懒加载：模型仅在首次查询时加载，启动零开销
- 单例模式：避免重复创建Milvus连接和模型实例

### 2.2 BM25全文检索分支

**核心公式：** Okapi BM25

```
score(q,d) = Σ IDF(qi) × tf(qi,d) × (k1+1) / (tf(qi,d) + k1×(1-b+b×dl/avgdl))
```

**分词方案：** jieba精确模式 + 中文停用词过滤（40+个虚词）

```python
# search.py — BM25Index
STOP_WORDS = set(['的', '了', '在', '是', '我', '有', '和', ...])

def _tokenize(text):
    words = list(jieba.cut(text))  # jieba精确模式
    return [w for w in words if len(w) >= 1 and w not in STOP_WORDS]
```

**倒排索引结构：**
- `postings`：词项 → {文档索引: 词频}
- `df`：词项 → 文档频率
- `avg_dl`：平均文档长度（用于长度归一化）

**优化点：**
- BM25参数 k1=1.5, b=0.75（经典参数，平衡词频饱和与文档长度惩罚）
- 仅存储非零分数结果，跳过得分为0的文档
- 与向量检索并行执行，总耗时取决于较慢分支

### 2.3 RRF融合算法

**核心思想：** 将多路检索的排名归一化后相加，避免分数尺度不一致的问题

```python
# rag_pipeline.py — RRF融合
def _rrf_fusion(rankings, k=60):
    """
    RRF_score(d) = Σ 1/(k + rank_i(d))
    k=60：论文推荐值，平衡头部和尾部文档的权重
    """
    doc_scores = {}
    doc_count = {}  # 命中路数（用于boost）

    for ranking in rankings:
        for rank, doc in enumerate(ranking):
            dedup_key = doc.get('text', '')[:80]
            rrf_score = 1.0 / (k + rank + 1)
            if dedup_key in doc_scores:
                doc_scores[dedup_key] = (doc_scores[dedup_key][0] + rrf_score, doc)
                doc_count[dedup_key] += 1
            else:
                doc_scores[dedup_key] = (rrf_score, doc)
                doc_count[dedup_key] = 1

    # 多路命中bonus：两路都出现的文档更可靠，每多命中一路 ×1.3
    for dedup_key, (score, doc) in doc_scores.items():
        count = doc_count[dedup_key]
        final_score = score * (1.3 ** (count - 1))
        doc['rrf_score'] = round(final_score, 6)

    results.sort(key=lambda x: x['rrf_score'], reverse=True)
    return results
```

**优化点：**
- 多路命中bonus（×1.3）：两路都召回的文档更可靠
- 文本前80字符作为去重键，避免重复计算
- RRF不依赖原始分数尺度，天然兼容向量检索（0~1）和BM25（0~∞）的分数

### 2.4 检索模式切换

支持三种模式动态切换：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| `hybrid` | 向量+BM25+RRF融合 | 默认，综合效果最佳 |
| `vector` | 仅向量检索 | 语义理解为主的问题 |
| `bm25` | 仅BM25检索 | 关键词精确匹配为主 |

```python
# rag_pipeline.py — 模式切换
def set_search_mode(self, mode, vector_weight=None, bm25_weight=None):
    if mode in ('vector', 'bm25', 'hybrid'):
        self.search_mode = mode
    # 权重归一化：确保 vector_weight + bm25_weight = 1
    total = self.vector_weight + self.bm25_weight
    if total > 0:
        self.vector_weight /= total
        self.bm25_weight /= total
```

## 三、Reranker重排序

### 3.1 bge-reranker-v2-m3 交叉编码器

与双塔模型（bge-m3）不同，交叉编码器同时接收query和document，计算精细的相关性分数：

```python
# models.py — RerankerClient
class RerankerClient:
    MODEL_DIR = 'model/bge-reranker-v2-m3'

    def rerank(self, query, documents, top_k=10, max_length=256):
        # 构建query-document对
        texts = [extract_text(doc)[:max_length] for doc in documents]
        pairs = [[query[:128], text] for text in texts]

        # 单batch推理，避免多次forward
        scores = self._model.predict(pairs, batch_size=len(pairs))

        # sigmoid归一化到 [0, 1]
        normalized_scores = 1 / (1 + np.exp(-np.array(scores)))

        # 保留原始dict所有字段，追加score
        results = []
        for doc, score in zip(documents, normalized_scores):
            item = {**doc, 'score': float(score)}
            results.append(item)

        results.sort(key=lambda x: x['score'], reverse=True)
        return results[:top_k]
```

**优化点：**
- 单batch推理：`batch_size=len(pairs)` 一次forward处理所有候选
- 文本截断：query截断128字，document截断256字，减少tokenizer开销
- 手动设备迁移：`self._model.model.to(device)` 修复CrossEncoder的device参数不可靠问题
- sigmoid归一化：将raw score映射到 [0,1] 区间，便于与其他分数对比

```python
    _instance = None
    _model = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def _load_model(self):
        if self._model is not None:
            return
        self._model = SentenceTransformer(self.MODEL_DIR, device=device)
```

**同样适用于：** `RerankerClient`、`MilvusStore`

**优势：**
- 避免重复加载模型（bge-m3约1.2GB，bge-reranker约1.1GB）
- 避免重复创建Milvus连接
- 首次查询时加载，启动零开销

## 十二、与前序工单的技术演进

```
工单2: TF-IDF+SVD(128维) → Milvus向量检索 → LLM生成
         ↓ 引入深度学习嵌入
工单3: bge-m3(1024维) → Milvus向量检索 → 多文档路由 → LLM生成
         ↓ 引入对话记忆
工单5: bge-m3 + Milvus → Redis对话记忆 → 多轮对话
         ↓ 引入混合检索
工单6: bge-m3 + Milvus + BM25 + RRF + bge-reranker → 完整混合检索架构
```

**工单6的核心突破：**
1. **混合检索**：向量+BM25+RRF，取长补短
2. **Reranker重排序**：bge-reranker交叉编码器，从"召回"到"精排"
3. **检索模式可配置**：用户可动态切换vector/bm25/hybrid
4. **代码架构统一**：三个合并文件（llm.py, models.py, search.py），结构更清晰
