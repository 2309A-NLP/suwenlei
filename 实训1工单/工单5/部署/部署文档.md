# RAG工单5 部署文档

## 1. 项目概述

### 1.1 项目简介
RAG工单5是一个基于PDF文档的智能问答系统，支持多文档路由检索和多轮对话记忆。系统通过解析PDF文档（招股说明书）构建向量数据库，实现对文档内容的语义检索和问答。

### 1.2 核心功能
- **多文档独立向量库**：每个PDF生成独立CSV和独立Milvus集合
- **查询路由**：根据问题内容自动判断搜索哪个文档的向量库
- **多轮对话记忆**：支持上下文理解，支持指代消解
- **中英文支持**：支持中文和英文问答
- **对比分析**：RAG检索 vs 纯LLM回答对比

### 1.2 技术架构
```
用户请求 → FastAPI后端 → 查询理解 → 文档路由 → Milvus/TF-IDF检索 → LLM生成 → 返回答案
                                    ↓
                              Redis对话记忆
```

## 2. 环境要求

### 2.1 操作系统
- Windows 10/11
- WSL (Windows Subsystem for Linux)

### 2.2 Python环境
- Python 3.11+（推荐使用项目自带的.venv虚拟环境）
- 虚拟环境路径：`E:\桌面\工单\RAG工单5\.venv`

### 2.3 依赖服务
- **Milvus**：向量数据库（运行在Windows上，端口19530）
- **Redis**：对话记忆存储（端口6379）
- **DeepSeek API**：大语言模型API

## 5. API接口说明

### 5.1 健康检查
```
GET /api/health
```
返回服务状态、引擎状态、后端类型、Redis可用性等信息。

### 5.2 文件上传
```
POST /api/upload
Content-Type: multipart/form-data
```
上传PDF文件，自动完成解析+分块+向量+Milvus入库。

### 5.3 文件列表
```
GET /api/files
```
获取已上传的文件列表。

### 5.4 删除文件
```
DELETE /api/files/{filename}
```
删除指定的上传文件及对应的CSV分块文件。

### 5.5 知识库重载
```
POST /api/reload
```
重新加载知识库（从CSV重新加载，不重新解析PDF）。

### 5.6 问答接口
```
POST /api/ask
Content-Type: application/json

{
  "question": "问题内容",
  "top_k": 5,
  "conversation_id": "可选的会话ID",
  "lang": "zh"
}
```
核心问答接口，支持中英文和多轮对话。

### 5.7 对比接口
```
POST /api/compare
Content-Type: application/json

{
  "question": "问题内容",
  "top_k": 5,
  "conversation_id": "可选的会话ID",
  "lang": "zh"
}
```
同时返回RAG（基于PDF检索）和纯LLM（无上下文）的回答，用于对比分析。

### 5.8 对话历史查询
```
GET /api/conversations/{conversation_id}
```
获取指定会话的对话历史。

### 5.9 删除对话
```
DELETE /api/conversations/{conversation_id}
```
删除指定会话的对话历史。

### 5.10 清空所有对话
```
DELETE /api/conversations
```
清空所有会话的对话历史。

### 5.11 查询理解调试
```
GET /api/understand?q=问题内容
```
返回查询理解结果（意图识别、扩展查询等）。

### 5.12 路由调试
```
GET /api/debug_route?q=问题内容
```
返回路由结果和检索来源。

## 7. 使用说明

### 7.1 上传文档
1. 访问前端页面 `http://localhost:8888`
2. 点击"上传文件"按钮
3. 选择PDF文件上传
4. 系统自动完成解析、分块、向量化、入库

### 7.2 提问问答
1. 在输入框输入问题
2. 选择语言（中文/英文）
3. 点击"提问"或"对比分析"
4. 查看回答结果和引用来源

### 7.3 多轮对话
1. 首次提问后，系统会生成一个`conversation_id`
2. 后续提问时传入`conversation_id`，系统会自动关联对话历史
3. 支持指代消解（如"这个公司"、"那XX呢"）

### 7.4 对比分析
使用`/api/compare`接口可以同时查看：
- **RAG回答**：基于PDF检索的回答
- **纯LLM回答**：不使用文档上下文的回答
- **对比分析**：两种回答的一致性、详细程度等

## 8. 常见问题

### 8.1 服务启动失败
- 检查端口是否被占用
- 检查Python依赖是否完整安装
- 检查Milvus服务是否正常运行
- 检查Redis服务是否正常运行

### 8.2 上传文件失败
- 确认文件格式为PDF
- 检查uploads目录权限
- 查看控制台错误日志

### 8.3 检索结果不准确
- 检查Milvus向量数据库是否正常
- 尝试调整top_k参数
- 使用`/api/debug_route`调试路由结果

### 8.4 LLM回答不准确
- 检查DeepSeek API密钥是否有效
- 查看API调用日志
- 尝试使用对比接口分析差异

### 8.5 对话记忆不工作
- 检查Redis服务是否正常运行
- 查看`/api/health`中的`redis_available`字段
- Redis不可用时会自动降级为内存存储（进程重启丢失）

## 9. 开发说明

1. 将PDF文件放入`uploads`目录
2. 调用`/api/upload`接口上传
3. 系统自动完成解析和入库

### 9.2 修改路由规则
编辑`rag_pipeline.py`中的`STRONG_KEYWORDS`和`WEAK_KEYWORDS`配置。

### 9.3 自定义提示词
编辑`rag_pipeline.py`中的`build_prompt`方法。

## 11. 与前序工单的对比

| 特性 | RAG工单4 | RAG工单5 |
|------|----------|----------|
| 多轮对话 | 不支持 | 支持（Redis存储） |
| 对话记忆 | 无 | 支持（最近3轮历史） |
| 指代消解 | 不支持 | 支持（结合对话历史） |
| 会话管理 | 无 | 支持（查询/删除/清空） |
| 降级策略 | Milvus→TF-IDF | Milvus→TF-IDF，Redis→内存 |
