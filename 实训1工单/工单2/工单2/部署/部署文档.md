> **工单编号**：人工智能NLP-RAG-基于PDF文档的问答系统优化  
> **文档版本**：V1.0  
> **更新日期**：2025-02-06

## 一、项目简介

本项目是一个基于 **RAG（Retrieval-Augmented Generation）** 架构的PDF文档智能问答系统，针对武汉兴图新科电子股份有限公司招股意向书进行全文解析和问答。

### 核心功能
- **PDF文档解析**：使用 PyMuPDF 解析PDF，自动提取文本、表格，去除页眉页脚和目录页
- **智能分块**：自适应段落边界分块，支持分块大小和重叠度配置
- **Query Understanding**：意图识别、消歧、问题分解、查询扩展
- **向量检索**：Milvus向量数据库检索（可选） + TF-IDF本地检索（默认降级方案）
- **LLM生成**：DeepSeek API 优先 + 本地提取回退策略
- **多语言支持**：支持中文和英文问答，英文自动翻译为中文检索再翻译回英文
- **对比分析**：RAG检索回答 vs 纯LLM回答的对比模式
- **Web前端**：单页应用，支持拖拽上传、语音输入、快捷提问

### 技术架构

```
用户 → 前端(index.html) → FastAPI(app.py)
                              ↓
                    Query Understanding
                              ↓
                    PDF Parser → CSV分块 → Milvus / TF-IDF检索
                              ↓
                    LLM Client (DeepSeek API / 本地提取)
                              ↓
                          返回答案
```

## 四、配置说明

### 4.1 环境变量

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `DEEPSEEK_API_KEY` | 代码内置key | DeepSeek API密钥，优先使用环境变量 |
| `RAG_BACKEND` | `auto` | RAG检索后端，`auto`=自动选择（Milvus优先→TF-IDF降级） |

### 4.2 配置文件

本项目无独立配置文件，关键配置在源代码中定义：

| 文件 | 关键配置 | 说明 |
|------|----------|------|
| `app.py` | `PDF_PATH` | 默认PDF文件路径 |
| `app.py` | `UPLOAD_DIR` | 上传文件目录 |
| `llm_client.py` | `DEEPSEEK_API_KEY` | API密钥 |
| `llm_client.py` | `DEEPSEEK_BASE_URL` | API地址（`https://api.deepseek.com`） |
| `pdf_parser/pdf_processor.py` | `CHUNK_SIZE` | 分块大小（默认1000字符） |
| `pdf_parser/pdf_processor.py` | `CHUNK_OVERLAP` | 分块重叠（默认150字符） |
| `milvus_store.py` | `host/port` | Milvus连接地址（默认`localhost:19530`） |

### 4.3 DeepSeek API配置

如需修改API密钥，设置环境变量：

```bash
export DEEPSEEK_API_KEY="sk-your-api-key-here"
```

> **注意**：若未配置有效API密钥，系统将使用本地提取模式生成回答，功能受限。

## 五、启动步骤

### 5.1 预处理PDF（首次必须）

在启动服务前，必须先运行PDF预处理生成CSV分块文件：

```bash
cd /mnt/e/桌面/工单/RAG工单2
source venv/bin/activate

# 方式一：使用默认PDF文件
python -m pdf_parser.pdf_processor 招股说明书1.pdf

# 方式二：指定输出路径
python -m pdf_parser.pdf_processor 招股说明书1.pdf -o 招股说明书1_chunks_v2.csv
```

> **说明**：此步骤生成 `招股说明书1_chunks_v2.csv` 文件，RAG引擎启动时从此文件加载分块数据。

### 5.2 启动Web服务

```bash
# 启动服务（自动查找可用端口，从8888开始）
python app.py
```

启动成功后控制台会显示：

```
========================================================
  RAG 问答系统 — 后端服务（仅CSV加载）
  PDF: /path/to/招股说明书1.pdf
  CSV: /path/to/招股说明书1_chunks_v2.csv
  上传目录: /path/to/uploads (N 个文件)
  后端模式: auto
  Query Understanding: 已启用
  文件上传: /api/upload (POST)
  对比接口: /api/compare (POST)
```

### 5.3 访问系统

启动成功后在浏览器中访问：

```
http://127.0.0.1:8888
```

> 端口可能自动调整为8889、8890等，请以控制台实际输出为准。

### 5.4 通过前端上传PDF（可选）

启动后也可通过Web界面上传PDF文件：
1. 点击页面顶部"文件管理"展开面板
2. 拖拽PDF文件到上传区域，或点击选择文件
3. 点击"📤 上传文件"按钮
4. 系统自动完成：PDF解析 → CSV分块 → TF-IDF嵌入 → Milvus入库
5. 点击"🔄 重载知识库"刷新引擎

## 七、API接口说明

### 7.1 问答接口

**`POST /api/ask`**

请求体：
```json
{
  "question": "武汉兴图新科电子股份有限公司注册资本是多少？",
  "top_k": 5,
  "lang": "zh"
}
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `question` | string | 必填 | 用户问题 |
| `top_k` | int | 5 | 检索返回的文档块数量 |
| `lang` | string | `zh` | 语言：`zh`中文 / `en`英文 |

响应体：
```json
{
  "question": "武汉兴图新科电子股份有限公司注册资本是多少？",
  "answer": "根据招股说明书，武汉兴图新科电子股份有限公司的注册资本为5,520.00万元。",
  "sources": [
    {"page": 15, "score": 0.85, "snippet": "..."}
  ],
  "time_seconds": 1.23,
  "gt_matched": true,
  "intent": "entity"
}
```

### 7.2 对比分析接口

**`POST /api/compare`**

同时返回 RAG检索回答 和 纯LLM回答，用于对比分析。

请求体同 `/api/ask`。

### 7.3 文件管理接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/upload` | 上传PDF文件（自动解析+分块+入库） |
| `GET` | `/api/files` | 获取已上传文件列表 |
| `DELETE` | `/api/files/{filename}` | 删除指定文件 |

### 7.4 其他接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/health` | 健康检查 |
| `POST` | `/api/reload` | 重载知识库 |
| `GET` | `/api/understand?q=问题` | Query Understanding调试 |
| `GET` | `/api/evaluate` | 获取评测结果（需先运行qa_eval.py） |
| `GET` | `/api/ground_truth` | 获取标准答案列表 |
| `GET` | `/` | 前端页面 |

## 八、常见问题

### Q1: 启动时报"CSV分块文件不存在"

**原因**：未运行PDF预处理步骤。  
**解决**：
```bash
python -m pdf_parser.pdf_processor 招股说明书1.pdf
```

### Q2: Milvus连接失败，提示"降级为TF-IDF检索"

**原因**：未安装pymilvus或未启动Milvus服务。  
**解决**：
- 无需处理，系统已自动降级为TF-IDF本地检索
- 如需使用Milvus，执行 `pip install pymilvus` 并启动Milvus服务

### Q3: DeepSeek API调用失败

**原因**：API密钥未配置或无效，网络不通。  
**解决**：
1. 检查环境变量 `DEEPSEEK_API_KEY` 是否正确设置
2. 确认网络可访问 `https://api.deepseek.com`
3. API不可用时系统自动回退到本地提取模式

### Q4: 上传PDF后无法问答

**原因**：上传后引擎未自动重载。  
**解决**：
- 系统会自动重载引擎，如未生效，点击"🔄 重载知识库"
- 或调用 `POST /api/reload` 接口

### Q5: 中文问答质量不佳

**优化方向**：
1. 确认PDF预处理生成了CSV分块文件
2. 检查分块大小是否合适（默认1000字符）
3. 确认DeepSeek API可用（本地提取模式效果有限）

### Q6: 英文问答结果为中文

**原因**：系统内部始终用中文检索和生成，再翻译为英文。  
**说明**：这是设计行为，确保检索准确率。若API不可用，翻译可能失败返回中文原文。

## 九、注意事项

### 9.1 安全注意

1. **API密钥安全**：`DEEPSEEK_API_KEY` 不应提交到版本控制系统
2. **服务绑定**：默认绑定 `127.0.0.1`，仅本机可访问，如需外部访问请修改 `app.py` 中的 `host` 参数
3. **文件上传**：仅接受 `.pdf` 格式文件，上传文件存储在 `uploads/` 目录

### 9.2 性能注意

1. **首次启动较慢**：首次加载需要初始化TF-IDF模型，后续查询响应更快
2. **响应时间**：目标 ≤3秒，实际取决于DeepSeek API响应速度和文档分块数量
3. **并发限制**：单实例Uvicorn服务，高并发场景建议使用 Gunicorn + Uvicorn 多Worker部署

### 9.3 文件管理

1. PDF预处理生成的CSV文件命名规则：`{PDF文件名}_chunks_v2.csv`
2. 删除已上传文件时，对应的CSV分块文件也会被删除
3. 上传目录 `uploads/` 请勿手动修改，由系统管理

### 9.4 开发调试

1. 使用 `GET /api/understand?q=问题` 调试Query Understanding模块
2. 使用 `GET /api/ground_truth` 查看标准答案
3. 使用对比模式（`POST /api/compare`）分析RAG vs 纯LLM效果
4. 日志级别为 `INFO`，可通过修改 `logging.basicConfig(level=logging.DEBUG)` 获取更详细日志

### 9.5 工单要求

根据工单验收标准：
- ✅ 问答准确率 ≥ 90%
- ✅ 响应时间 ≤ 3秒
- ✅ 支持中英文问答
- ✅ 提供对比分析功能（RAG vs 纯LLM）
- ✅ 支持文件上传和知识库动态更新
- ✅ 具备容错机制（API失败→本地提取降级，Milvus失败→TF-IDF降级）
