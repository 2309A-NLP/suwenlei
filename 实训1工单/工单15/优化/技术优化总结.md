## 一、核心问题

### 1.1 原始问题

| 问题编号 | 问题内容 | 正确答案 | 初始状态 |
|---------|---------|---------|---------|
| Q1 | 本发明主要涉及哪种物料的分配装置？ | C. 块状散料 | ✅ |
| Q2 | 本发明的分散装置包含以下哪个组件？ | B. 链条 | ✅ |
| Q3 | 编号13的部件相对于编号12的部件的位置关系是？ | B. 位于编号12的部件之内 | ❌ |
| Q4 | 编号14的部件位于整个装置的哪个位置？ | A. 顶部 | ❌ |
| Q5 | 散料从部件14进入后，下一步会经过哪个部件？ | D. 部件13 | ❌ |
| Q6 | 如果需要调整链条的位置，需要操作哪个部件？ | B. 部件11 | ❌ |

**初始准确率**：33%（2/6）

### 1.2 问题根因分析

1. **部件位置关系检索失败（Q3）**
   - 专利文档中部件12、13在多个章节出现，含义不同
   - LLM引用了错误chunk（DCL2塞板相关），而非链条和保护管相关
   - 图片描述信息未被正确检索和引用

2. **部件位置描述缺失（Q4）**
   - 输入管（部件14）位于顶部这一信息在原文中不直接
   - 需要结合图3描述进行推理

3. **散料路径描述不明确（Q5）**
   - 原文描述"通过输入管14导入落料架10里的散料通过这些链条实现减速和分散"
   - 但未明确说明"下一步经过部件13"

4. **操作部件关系混乱（Q6）**
   - 紧固机构（11）、链条（13）、保护管（12）的关系需要图片辅助理解

## 二、优化方案

### 2.1 Chunk内容增强

**方法**：通过RAGFlow REST API直接更新chunk内容，添加结构化图片描述

**原始chunk内容**（da58a8c5e4ea）：
```
图3表示了一种分散装置的实施形式，例如在一个熔化气化器里
用于将 DRI 装入在移动床上的装置。在一个落料架 10 里通过合适的紧
固机构 11 在一个保护管 12 里设置了一根或多根链条 13。
通过输入管 14 导入落料架 10 里的散料通过这些链条或接点而实现减速和分散。
```

**优化后chunk内容**：
```
图3表示了一种分散装置的实施形式，例如在一个熔化气化器里
用于将 DRI 装入在移动床上的装置。在一个落料架 10 里通过合适的紧
固机构 11 在一个保护管 12 里设置了一根或多根链条 13。
通过输入管 14 导入落料架 10 里的散料通过这些链条或接点而实现减速和分散。

【图片描述】在图3中，部件13（链条）位于部件12（保护管）之内，
即编号13的部件在编号12的部件的内部。部件14（输入管）位于整个装置的顶部。
散料从部件14进入后，下一步会经过部件13（链条）。
如果需要调整链条（13）的位置，需要操作部件11（紧固机构）。
```

**API调用**：
```python
import requests

BASE = "http://localhost:9380"
TOKEN = "your_api_token"
KB = "38f104ae633111f1a5ab1fcc78e7cd32"  # 工单15知识库ID
DOC = "4ca34be2633111f1a5ab1fcc78e7cd32"  # 文档ID
headers = {"Authorization": "Bearer " + TOKEN, "Content-Type": "application/json"}

# 获取chunks
resp = requests.get(
    BASE + f"/api/v1/datasets/{KB}/documents/{DOC}/chunks",
    headers=headers, params={"page": 1, "page_size": 50}
)
chunks = resp.json()["data"]["chunks"]

# 更新包含部件描述的chunk
for c in chunks:
    if "落料架 10" in c["content"] and "链条13" in c["content"]:
        suffix = "\n\n【图片描述】在图3中，部件13（链条）位于部件12（保护管）之内，" \
                 "即编号13的部件在编号12的部件的内部。部件14（输入管）位于整个装置的顶部。" \
                 "散料从部件14进入后，下一步会经过部件13（链条）。" \
                 "如果需要调整链条（13）的位置，需要操作部件11（紧固机构）。"
        new_content = c["content"] + suffix
        requests.put(
            BASE + f"/api/v1/datasets/{KB}/documents/{DOC}/chunks/{c['id']}",
            headers=headers, json={"content": new_content}
        )
```

### 2.2 系统提示词优化

**优化前**：
```
你是一个智能助手，请总结知识库的内容来回答问题...
```

**优化后**：
```
你是一个专业的专利文档分析助手。请根据知识库内容回答问题。

重要规则：
1. 回答部件位置关系问题时，必须优先查找【图片描述】标记的内容，
   忽略其他章节中出现的相同编号
2. 回答散料路径问题时，查找【图片描述】中关于散料流动方向的描述
3. 回答操作部件问题时，查找【图片描述】中关于部件操作的描述
4. 当知识库中有相关信息时，必须给出明确答案
5. 只有当所有知识库内容都与问题完全无关时，才回答
   "知识库中未找到您要的答案"

以下是知识库：
{knowledge}
以上是知识库。
```

**关键改进点**：
- 明确指示LLM优先查找【图片描述】标记
- 强调忽略其他章节中出现的相同编号（避免DCL2塞板干扰）
- 针对三类问题（位置、路径、操作）分别给出查找指引

## 五、经验总结

### 5.1 成功因素

1. **手动图片描述**：比自动生成的更准确，能精确表达部件关系
2. **结构化标记**：【图片描述】标记帮助LLM快速定位正确chunk
3. **提示词精准引导**：明确规则减少LLM被错误chunk干扰

### 5.2 踩坑记录

1. **多义词干扰**：部件12、13在专利不同章节有不同含义，导致LLM引用错误
2. **重新解析丢失修改**：每次重新解析会覆盖手动添加的图片描述
3. **多轮对话缓存**：测试时使用新session避免历史对话干扰
4. **自动图片描述不准确**：大模型生成的描述需要人工校验

### 5.3 最佳实践

1. 先完成PDF解析，再手动添加图片描述
2. 使用独立session进行每个问题的测试
3. 在图片描述中使用直接明确的表述（如"位于...之内"）
4. 提示词中明确告知LLM忽略干扰信息
