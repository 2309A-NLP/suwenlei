# RAG工单4 部署文档

## 1. 项目概述

### 1.1 项目简介
RAG工单4是一个基于PDF文档的智能问答系统，支持多文档路由检索。系统通过解析PDF文档（招股说明书）构建向量数据库，实现对文档内容的语义检索和问答。

### 1.2 核心功能
- **多文档独立向量库**：每个PDF生成独立CSV和独立Milvus集合
- **查询路由**：根据问题内容自动判断搜索哪个文档的向量库
- **PDF解析增强**：水印去除 + Qwen-VL多模态图片识别 + 文本清理
- **中英文支持**：支持中文和英文问答
- **对比分析**：RAG检索 vs 纯LLM回答对比

### 1.3 技术架构
```
用户请求 → FastAPI后端 → 查询理解 → 文档路由 → Milvus/TF-IDF检索 → LLM生成 → 返回答案
```

## 4. 安装部署

```bash
# 在Windows上启动Milvus（默认端口19530）
# 确保Milvus服务正在运行
```


## 5. API接口说明

### 5.1 健康检查
```
GET /api/health
```
返回服务状态、引擎状态、后端类型等信息。

### 5.2 文件上传
```
POST /api/upload
Content-Type: multipart/form-data
```
上传PDF文件，自动完成解析+分块+向量+Milvus入库。

### 5.3 文件列表
```
GET /api/files
```
获取已上传的文件列表。

### 5.4 删除文件
```
DELETE /api/files/{filename}
```
删除指定的上传文件及对应的CSV分块文件。

### 5.5 知识库重载
```
POST /api/reload
```
重新加载知识库（从CSV重新加载，不重新解析PDF）。

### 5.6 问答接口
```
POST /api/ask
Content-Type: application/json

{
  "question": "问题内容",
  "top_k": 25,
  "lang": "zh"
}
```
核心问答接口，支持中英文。

### 5.7 对比接口
```
POST /api/compare
Content-Type: application/json

{
  "question": "问题内容",
  "top_k": 25,
  "lang": "zh"
}
```
同时返回RAG（基于PDF检索）和纯LLM（无上下文）的回答，用于对比分析。

### 5.8 查询理解调试
```
GET /api/understand?q=问题内容
```
返回查询理解结果（意图识别、扩展查询等）。

### 5.9 路由调试
```
GET /api/debug_route?q=问题内容
```
返回路由结果和检索来源。

## 7. 使用说明

### 7.1 上传文档
1. 访问前端页面 `http://localhost:8888`
2. 点击"上传文件"按钮
3. 选择PDF文件上传
4. 系统自动完成解析、分块、向量化、入库

### 7.2 提问问答
1. 在输入框输入问题
2. 选择语言（中文/英文）
3. 点击"提问"或"对比分析"
4. 查看回答结果和引用来源

### 7.3 对比分析
使用`/api/compare`接口可以同时查看：
- **RAG回答**：基于PDF检索的回答
- **纯LLM回答**：不使用文档上下文的回答
- **对比分析**：两种回答的一致性、详细程度等

## 8. 常见问题

### 8.1 服务启动失败
- 检查端口是否被占用
- 检查Python依赖是否完整安装
- 检查Milvus服务是否正常运行

### 8.2 上传文件失败
- 确认文件格式为PDF
- 检查uploads目录权限
- 查看控制台错误日志

### 8.3 检索结果不准确
- 检查Milvus向量数据库是否正常
- 尝试调整top_k参数
- 使用`/api/debug_route`调试路由结果

### 8.4 LLM回答不准确
- 检查DeepSeek API密钥是否有效
- 查看API调用日志
- 尝试使用对比接口分析差异

## 9. 开发说明

### 9.1 添加新的PDF文档
1. 将PDF文件放入`uploads`目录
2. 调用`/api/upload`接口上传
3. 系统自动完成解析和入库

### 9.2 修改路由规则
编辑`rag_pipeline.py`中的`DOC_KEYWORDS`和`STRONG_KEYWORDS`/`WEAK_KEYWORDS`配置。

### 9.3 自定义提示词
编辑`rag_pipeline.py`中的`build_prompt`方法。
