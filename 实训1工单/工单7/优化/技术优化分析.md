# RAG工单7 技术优化分析

## 一、项目定位与核心架构

RAG工单7是混合检索系统的**多语言增强版本**，在工单6（混合检索+Reranker）基础上，引入了三大核心升级：

```
用户查询（中/英文）
  ↓
查询理解
  ├── 意图识别（8种中英文意图模式）
  ├── 实体消歧（40+中文别名 + 20+英文别名）
  ├── 问题分解（分号/句号/并列）
  └── 查询扩展（中文同义词 + 英文同义词）
  ↓
LLM智能路由（DeepSeek API自动判断目标文档）  ← 工单7新增
  ↓
┌─────────────────────────────────────────┐
│  向量检索（bge-m3 + Milvus）            │
│  BM25全文检索（jieba分词 + 倒排索引）     │
│  RRF融合（Reciprocal Rank Fusion）       │
└─────────────────────────────────────────┘
  ↓
Reranker重排序（bge-reranker-v2-m3）
  ↓
关键词补全检索（兜底召回）
  ↓
LLM生成（三级降级：标准答案 → API → 本地提取）
  ↓
答案返回（中/英文，含来源、分数、对话历史）
```

**与前序工单的架构演进：**

| 维度 | 工单5 | 工单6 | 工单7 |
|------|-------|-------|-------|
| 嵌入模型 | bge-m3 | bge-m3 | bge-m3 |
| 检索方式 | 仅向量 | 混合（向量+BM25+RRF） | 混合（向量+BM25+RRF） |

## 二、LLM智能路由（核心创新）

### 2.1 从关键词匹配到语义理解

工单6的路由依赖手工维护的关键词列表：

```python
# 工单6：关键词匹配路由（需手动维护）
STRONG_KEYWORDS = {
    '招股说明书1': ['兴图', '兴图新科', '武汉兴图', '程家明', 'C4ISR', '视频指挥'],
    '招股说明书2': ['力源', '力源信息', '武汉力源', '赵马克', 'Mark Zhao', '融冰投资'],
}
```

工单7改为**LLM智能路由**，调用DeepSeek API自动判断：

```python
# 工单7：LLM智能路由（自动理解语义）
def _route_query(self, query):
    all_docs = list(self.doc_engines.keys())
    if len(all_docs) <= 1:
        return all_docs  # 单文档无需路由

    # 1. 构建文档摘要（每个文档取前3个分块的前100字符）
    doc_descriptions = []
    for doc_name, engine in self.doc_engines.items():
        summary = ""
        for chunk in engine.chunks[:3]:
            text = chunk.get('text', '')[:100]
            summary += text + " "
        doc_descriptions.append(f"- {doc_name}: {summary[:200].strip()}")

    # 2. 调用LLM判断哪些文档与问题相关
    prompt = f"""你是一个智能路由助手。根据用户的问题，从以下文档中选择最相关的文档。
可用文档列表：
{doc_list}
用户问题：{query}
请返回与问题相关的文档名称（多个用逗号分隔），如果所有文档都相关就返回"ALL"。"""

    r = requests.post(f'{DEEPSEEK_BASE_URL}/v1/chat/completions', ..., timeout=10)
    if r.status_code == 200:
        content = r.json()['choices'][0]['message']['content'].strip()
        if content.upper() == 'ALL':
            return all_docs
        matched = [name for name in content.split(',') if name in self.doc_engines]
        if matched:
            return matched

    # 3. LLM路由失败时搜索所有文档
    return all_docs
```

### 2.2 优势分析

| 维度 | 关键词路由（工单6） | LLM路由（工单7） |
|------|---------------------|-------------------|
| 维护成本 | 需手动维护关键词列表 | 无需维护，自动适应 |
| 语义理解 | 仅匹配关键词字面 | 理解问题语义含义 |
| 扩展性 | 新增文档需改代码 | 新增文档自动识别 |
| 准确率 | 依赖关键词覆盖度 | 依赖LLM理解能力 |
| 延迟 | 0ms（本地匹配） | ~1-3秒（API调用） |
| 可靠性 | 100%（不依赖外部） | 依赖API可用性 |

### 2.3 降级策略

```python
# 三级降级：
# 1. LLM API返回有效文档名 → 使用匹配的文档
# 2. LLM API返回"ALL" → 搜索所有文档
# 3. LLM API超时/失败/返回无法解析的内容 → 搜索所有文档
```

### 6.1 自动扫描逻辑

```python
# app.py — get_engine()中的PDF扫描
def get_engine():
    pdf_paths = {}
    # 1. 扫描BASE_DIR（项目根目录）下的所有PDF
    if os.path.isdir(BASE_DIR):
        for f in os.listdir(BASE_DIR):
            if f.lower().endswith('.pdf') and not f.startswith('~$'):
                pdf_name = os.path.splitext(f)[0]
                pdf_paths[pdf_name] = os.path.join(BASE_DIR, f)

    # 2. 扫描uploads目录下的PDF（不覆盖同名文件）
    if os.path.isdir(UPLOAD_DIR):
        for f in os.listdir(UPLOAD_DIR):
            if f.lower().endswith('.pdf') and not f.startswith('~$'):
                pdf_name = os.path.splitext(f)[0]
                if pdf_name not in pdf_paths:  # 仅添加不重复的文件
                    pdf_paths[pdf_name] = os.path.join(UPLOAD_DIR, f)
```

## 十一、与前序工单的技术演进


**工单7的核心突破：**
1. **LLM智能路由**：从"人工维护关键词"到"AI自动理解语义路由"
