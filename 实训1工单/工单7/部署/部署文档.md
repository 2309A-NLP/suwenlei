# RAG工单7 部署文档

## 1. 项目概述

### 1.1 项目简介
RAG工单7是混合检索增强生成系统的多语言版本，在工单6（混合检索）基础上，引入了**LLM智能路由**和**完整多语言支持**，能够自动识别问题应检索哪些文档，并支持中英文双向问答。

### 1.2 核心功能
- **混合检索**：向量检索 + BM25全文检索 + RRF融合
- **Reranker重排序**：bge-reranker-v2-m3交叉编码器 + 可选LLM重排
- **LLM智能路由**：调用DeepSeek API自动判断问题应检索哪些文档
- **完整多语言支持**：中英文实体消歧、同义词扩展、问答
- **用户反馈**：支持用户对问答结果进行评价
- **多轮对话记忆**：支持上下文理解和指代消解

### 1.3 技术架构
```
用户请求（中/英文）
  ↓
查询理解（意图识别 → 实体消歧[中英文] → 问题分解 → 查询扩展[中英文]）
  ↓
LLM智能路由（DeepSeek API自动判断目标文档）
  ↓
┌─────────────────────────────────────────┐
│  向量检索（bge-m3 + Milvus）            │  ← 语义相似度召回
│  BM25全文检索（jieba分词 + 倒排索引）     │  ← 关键词精确匹配
│  RRF融合（Reciprocal Rank Fusion）       │  ← 多路结果归一化合并
└─────────────────────────────────────────┘
  ↓
Reranker重排序（bge-reranker-v2-m3）     ← 交叉编码器精细打分
  ↓
关键词补全检索（兜底召回）                ← 保证召回率
  ↓
LLM生成（三级降级：标准答案 → API → 本地提取）
  ↓
答案返回（中/英文，含来源、分数、对话历史）
```

### 1.4 与工单6的核心差异

| 维度 | 工单6 | 工单7 |
|------|-------|-------|
| 文档路由 | 关键词匹配（强/弱） | **LLM智能路由**（DeepSeek API） |
| 多语言 | 基础中英文 | **完整多语言**（20+英文别名+英文同义词+英文停用词） |
| Prompt | 中文模板 | **英文模板**（支持中英文双语） |
| 用户反馈 | 无 | **新增 /api/feedback 接口** |
| 模型预加载 | 启动时加载 | **强制预加载+绑定KnowledgeBuilder** |
| PDF扫描 | 固定路径 | **自动扫描BASE_DIR下所有PDF** |
| 警告处理 | 无 | **屏蔽PyMilvus/jieba弃用警告** |
| 临时文件 | 不过滤 | **排除~$开头的临时文件** |

### 2.1 操作系统

- WSL (Windows Subsystem for Linux)

- Python 3.11+（推荐使用项目自带的.venv虚拟环境）

## 5. API接口说明

### 5.1 健康检查
```
GET /api/health
```
返回服务状态、引擎状态、LLM可用性、Redis可用性、嵌入模型/重排模型可用性。

### 5.2 文件上传
```
POST /api/upload
Content-Type: multipart/form-data
```
上传PDF文件，自动完成解析+分块+向量+Milvus入库。**上传时复用GPU上的嵌入模型**。

### 5.3 文件列表
```
GET /api/files
```
获取已上传的文件列表。

### 5.4 删除文件
```
DELETE /api/files/{filename}
```
删除指定的上传文件及对应的CSV分块文件。

### 5.5 知识库重载
```
POST /api/reload
```
重新加载知识库。

### 5.6 问答接口
```
POST /api/ask
Content-Type: application/json

{
  "question": "问题内容",
  "top_k": 5,
  "conversation_id": "可选的会话ID",
  "search_mode": "hybrid",
  "lang": "zh"
}
```
核心问答接口，支持中英文和多轮对话。**lang参数：zh中文 / en英文**。

### 5.7 对比接口
```
POST /api/compare
Content-Type: application/json

{
  "question": "问题内容",
  "top_k": 5,
  "lang": "zh"
}
```
同时返回RAG和纯LLM的回答，含对比分析（一致性、详细程度、速度）。

### 5.8 检索配置接口
```
GET /api/search/config
POST /api/search/config
```
获取/设置检索模式和权重。

### 5.9 LLM重排接口
```
POST /api/rerank
```
用DeepSeek API对候选文档重新评分。

### 5.10 用户反馈接口（新增）
```
POST /api/feedback
Content-Type: application/json

{
  "question": "问题内容",
  "answer": "系统回答",
  "rating": "good",
  "comment": "可选评论"
}
```
记录用户对问答结果的评价，持久化到`feedback.jsonl`文件。

### 5.11 对话管理接口
```
GET /api/conversations/{conversation_id}     # 查询对话历史

### 5.12 调试接口
```
GET /api/understand?q=问题内容                # 查看查询理解结果

## 7. 使用说明

### 7.1 上传文档
1. 访问前端页面 `http://localhost:8888`
2. 点击"上传文件"按钮
3. 选择PDF文件上传
4. 系统自动完成解析、分块、向量化、入库

### 7.2 中文问答
1. 在输入框输入中文问题
2. 语言选择"中文"
3. 点击"提问"

### 7.3 英文问答
1. 在输入框输入英文问题（如"What is the registered capital?"）
2. 语言选择"英文"
3. 点击"提问"
4. 系统自动翻译→中文检索→翻译回英文

### 7.4 对比分析
使用`/api/compare`接口，同时查看：
- **RAG回答**：基于PDF检索的回答
- **纯LLM回答**：不使用文档上下文的回答
- **对比分析**：一致性、引用来源、详细程度、速度

### 7.5 用户反馈
对问答结果点击"有用/无用"按钮，反馈数据保存到`feedback.jsonl`。

### 7.6 检索模式切换
- **hybrid**：混合检索（向量+BM25+RRF融合）— 推荐
- **vector**：仅向量检索
- **bm25**：仅BM25全文检索

- **语义理解**：能理解问题的语义含义，而非仅匹配关键词

## 10. 常见问题

### 10.1 服务启动失败
- 检查端口是否被占用
- 检查Python依赖是否完整安装
- 检查Milvus服务是否正常运行
- 检查Redis服务是否正常运行
- 检查DeepSeek API密钥是否有效

### 10.2 上传文件失败
- 确认文件格式为PDF
- 检查uploads目录权限
- 查看控制台错误日志
- **确保GPU可用**：上传时会同步调用嵌入模型，CPU模式下会很慢

### 10.3 英文问答返回中文
- 检查DeepSeek API密钥是否有效（翻译依赖API）
- 检查`lang`参数是否设置为`"en"`
- 查看控制台翻译日志

### 10.4 LLM路由超时
- 检查网络连接和API可用性
- 路由失败会自动降级为全文档搜索
- 查看控制台`[LLM路由]`日志

### 10.5 用户反馈不保存
- 检查项目根目录写入权限
- 查看控制台`反馈保存失败`警告
